# Benchmark: precision, recall and F1

Generated by `python tools/benchmark.py report`; do not edit by hand. Per-rule precision: [benchmark/RESULTS.md](../benchmark/RESULTS.md).

## What is measured

- **Precision** comes from 1,592 findings on 53 pinned repositories, each read in the code and labelled true or false (both splits, preview rules included).
- **Recall** comes from two ground-truth sets: 17 known vulnerable locations in the repositories pinned at the commit before a published security advisory ([benchmark/recall.json](../benchmark/recall.json)), and 210 seeded cases (`expect:` markers in tests/fixtures and benchmark/seeded).
- Seeded cases are written by us, so seeded recall is optimistic: it shows that a rule works on the case it was written for. The advisory set is small but independent: nobody wrote those bugs for this tool.

## Limits

- The advisory set has 17 locations in 7 repositories: enough to show the kinds of bug that are missed, not a precise recall figure. More pre-fix repositories are added as advisories are published.
- Precision labels were made by the maintainers; a blind second labelling is in [docs/LABELLING.md](LABELLING.md).
- The tuned split flatters precision (rules were fixed while looking at it); the held-out split does not (see benchmark/RESULTS.md).
- "Detected" means a finding of a matching rule within 3 lines of the known location; a finding elsewhere in the same flow does not count.
