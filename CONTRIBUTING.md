# Contributing to vibeaudit

Thanks for helping. The most useful contributions, in order:

1. **False positives and missed findings**, reported with a minimal example: the smallest file (or few
   files) that shows the problem, what vibeaudit reported, and what you expected.
2. **Fixes for those**, with a test.
3. **New rules** for mistakes AI coding assistants keep making. Please open an issue first to agree on the
   scope and on how the rule avoids false alarms.

## Setting up

```bash
git clone https://github.com/Ashin-06/vibeaudit.git
```

```bash
cd vibeaudit
```

```bash
python -m pip install -e ".[dev]"
```

The package has no runtime dependencies on Python 3.11 and newer (`tomli` on 3.9 and 3.10), and the tests
need only pytest. They also run from a plain checkout without installing (`python -m pytest`).

## Checks to run before a pull request

```bash
python -m pytest -q
```

```bash
python tools/check_ascii.py
```

```bash
python tools/gen_rules_doc.py --check
```

```bash
vibeaudit scan . --external none --fail-on low
```

- `pytest` runs everything except the live network tests; `python -m pytest -m network` runs those
  (registry and OSV lookups, needs internet). Deeper runs: `VIBEAUDIT_FUZZ_ROUNDS=300` for the fuzzer and
  `VIBEAUDIT_PERF_FILES=10000` for the scale test.
- Every text file in the repository is plain ASCII (no curly quotes, no long dashes, no symbols);
  `tools/check_ascii.py` enforces it.
- vibeaudit scans itself with no findings; keep it that way (or add an inline ignore with a reason).

## How the code is organised

| Path | What is there |
| --- | --- |
| `src/vibeaudit/rules.py` | Every rule: id, title, category, severity, why, fix, CWE and OWASP references. |
| `src/vibeaudit/scanner.py` | Runs the scanners and turns raw findings into the result (suppression, baselines, feedback). |
| `src/vibeaudit/files.py` | Which files are in the project, and how they are read. |
| `src/vibeaudit/lexer.py` | Offset-preserving views of JS/TS and Python with comments and strings blanked. |
| `src/vibeaudit/pyscan.py`, `jsscan.py` | Routes, auth evidence and taint tracking for Python and JS/TS. |
| `src/vibeaudit/*scan.py`, `deps.py`, `contracts.py` | One module per area: secrets, project config, quality, data, reliability, AI, UI, dependencies, API contracts. |
| `src/vibeaudit/report.py` | Terminal, JSON, SARIF, Markdown, HTML, prompt and badge output, and the scores. |
| `tests/fixtures/` | Sample apps. Expected findings are marked with an `expect: RULE` comment on the line (or listed in `<fixture>.expected` for files that cannot hold comments). |
| `docs/RULES.md` | The rule catalogue, generated by `tools/gen_rules_doc.py`. |

## Writing a fix or a rule

- **Start with a failing test.** For a false positive or a missed finding, add the smallest code that shows
  it to a test (see `tests/test_audit_passes.py` for the style) and check that it fails before you change
  the scanner.
- **Fix the cause, not the example.** A fix that only matches the reported file will miss the next one.
- **Keep the sample apps exact.** If a rule should fire on a fixture, add an `expect:` marker; the clean
  app (`tests/fixtures/clean_app`) must stay free of findings.
- **Regular expressions must stay linear.** `tests/test_redos.py` times every module-level pattern against
  hostile input; bound repetitions (`{0,200}`) and avoid nested quantifiers.
- **Messages** say what is wrong at that line in plain words; the rule's `why` and `fix` explain the rest.
- **New rules** also need an entry in `rules.py`, a run over a few real repositories with every finding
  read, and `python tools/gen_rules_doc.py` to update the catalogue.

## Commits and pull requests

- One logical change per commit, with a message that says what changed and why.
- Add a line to `CHANGELOG.md` under an "Unreleased" heading for anything users would notice.
- By contributing you agree that your contribution is licensed under the MIT license of this project.

## Reporting a security problem

Please do not open a public issue for a vulnerability in vibeaudit itself; see [SECURITY.md](SECURITY.md).
